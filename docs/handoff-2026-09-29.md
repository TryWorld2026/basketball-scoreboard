## 1. 项目是什么

校园班赛的官方记分牌：**手机当遥控器，任何一块屏幕当大屏，打完自动出一张能甩进班群的数据卡**。

- 线上：https://score.tryworld.com.cn （自定义域名；`*.workers.dev` 国内被 DNS 污染）
- 仓库：https://github.com/TryWorld2026/basketball-scoreboard （MIT）
- 技术栈：Cloudflare Workers + D1 + 原生 ES Module，**运行时零依赖**（无框架、无构建、无第三方包）
- 定位边界（README 原话）：班赛工具，不是正式比赛系统。要用于正式比赛需加裁判身份与签名写路径。

### 三条撑起一切的设计决定

1. **客户端只发“意图”，服务端算状态。** 手机发“红队 +2”，不是“新比分=48”——否则两人同时按分必丢一个。
2. **时钟不跑在服务端。** 只存 `running + since + remainingMs`，任何设备自己推算，刷新/换设备/断网重连时钟连续。
3. **1 秒轮询，不做 WebSocket。** 比分晚一秒毫无感知，换来零长连接基础设施。

## 2. 架构

```
浏览器（原生 ES module，无框架无构建）
  ├─ /                    建赛 · 加入 · 找回控制权
  ├─ /room/:code          房间码 + 二维码 + 找回码区块
  ├─ /room/:code/control  控制端（手机遥控器）
  ├─ /room/:code/display  大屏（只读）
  └─ /room/:code/card     数据卡（canvas PNG + 操作记录面板）
        │  同源 /api/game?action=get|create|apply|log|recover
        ▼
Cloudflare Worker
  worker/index.js      入口：所有请求都过这里（run_worker_first: true）；
                       统一安全响应头；cron 每分钟到点推进
  worker/handler.mjs   参数校验 · 意图白名单 · 版本号 CAS 重放 · 控制凭证校验 ·
                       操作审计 · 控制权补发 · 到点推进 · 失败限流
  worker/rules.mjs     规则引擎（纯函数，比分/时钟/犯规/节次唯一事实来源）
  worker/ratelimit.mjs 进程内滑动窗口限流（只挡失败请求，不挡正常轮询）
  worker/store-d1.mjs  D1 适配器（换库只动这一层）
        ▼
Cloudflare D1   games 表：一场比赛一行，整场状态一个 JSON + version
                action_receipts：nonce 幂等回执（与 games 级联）
                action_log：操作审计（与 games 级联）
```

### 安全模型：三把钥匙

| 钥匙 | 能力 | 存储 |
|---|---|---|
| **4 位房间码** | 读一切：比分、大屏、数据卡、**操作记录** | 明文分享，本身就是凭证 |
| **控制令牌**（64 hex） | 写：记分/犯规/暂停/时钟/终局/重开 | 库里只存 SHA-256；创赛时明文只回一次，之后只活在建赛那台设备 |
| **找回码**（8 位 `XXXX-XXXX`） | 换发新的控制令牌（换发即换锁：旧令牌+旧码同时作废，新码可再次救援） | 库里只存 SHA-256，补发时轮换 |

限流按 IP 只统计失败请求（房间不存在/参数非法/冲突/凭证不符/找回码错误），正常 1 秒轮询不计次。进程内计数属尽力而为，挡不住分布式枚举——README「已知边界」写明了。

## 3. 数据模型（5 个迁移）

| 迁移 | 内容 |
|---|---|
| `0001_games.sql` | `games` 表：code PK / status / version / state(JSON) / created_at / updated_at |
| `0002_control_auth.sql` | `games.controller_hash`（可空，老行 fail closed 只读）；`action_receipts` 表 |
| `0003_receipt_attempt_id.sql` | `action_receipts.receipt_id`：证明 UPDATE 用的是**本次 INSERT** 的回执 |
| `0004_action_log.sql` | `action_log` 表：seq(=落地后 version) / actor / action / before_score / after_score / clock_ms / at |
| `0005_control_recovery.sql` | `games.recovery_hash`：控制找回码 |

**审计语义**（`action_log`，每次落地写一条，和状态更新同一个批处理）：
- 只记**真落地**：规则拒的、幂等拦下的、无变化的动作都不留痕
- `reset` 重开**不清**旧日志——终局被擦掉这件事本身必须可查
- `actor` = 控制凭证 SHA-256 前 8 位；`cron` 推进和 `recovery` 补发也有专属 actor
- 日志与比赛行级联删除（半途放弃局清理时一起走）

**部署顺序不能反**：Worker 读路径查 `controller_hash`、写路径要 `action_log`/`recovery_hash`。**先迁后推**，否则全站 503。

### 这个项目的测试规矩（违反=返工）

1. **每个新修复必须同时进 `dev/mutate.mjs`**，否则那条修复等于没被测到。变异体三要素：`file` / `from`（锚点，必须全文件唯一）/ `to` / `suite` / `mustRedOn`（必须红在哪条断言上）。
2. **测试变红必须非零退出**。曾出现攻击探针打印 `ATTACK` 却 `exit 0`，整张网不构成门禁。
3. **静态断言前先 `stripJs` 剥注释**。曾因注释里写着“必须走 navigator.share”，真调用被删光断言照样绿。
4. **改 `worker/rules.mjs` 的时钟逻辑必须同步 `public/js/clock.js`**，`parity` 会逐场景比对。
5. **「只在真浏览器里现形」的问题写成静态断言**（mobile.mjs 的存在理由），比如 `replaceChildren` 不吃 `false`。
6. **mutate.mjs 会识别「探针崩了」**：退出码非零但无 ATTACK/FAIL 文本 → 判 MISATTR 并贴崩因，不再误判成存活。

| 5 | 以为不声明 binding 也有默认 `env.ASSETS` | 生产里是 undefined → 全站 500；本地 dev 和测试桩都抓不到 |
| 6 | `replaceChildren(... cond && h(...))` 渲染出「false」 | 条件块用展开三元 `...(cond ? [h(...)] : [])` |
| 7 | 变异体把配置行换成注释 → 尾逗号 → JSON.parse 崩 → 误判 SURVIVED | mutate.mjs 已能识别「崩了」；探针解析配置要容忍尾逗号 |
| 8 | PowerShell 里 git push 显示 exit 1 | git 往 stderr 写进度，PS 把 stderr 当错误记录；看输出里的 `main -> main` 判断成败 |

| 10 | 变异测试锚点撞车 | `from` 必须在目标文件里**全文件唯一**，撞车会 SKIP（归属存疑）而非 killed |
